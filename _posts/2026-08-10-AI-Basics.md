# AI Basics

If you're just starting to learn about AI, the terminology can get confusing quickly. Here are some of the most common AI terms explained in plain English.

## Four terms worth understanding first

### LLM = Brain

Understands your request, reasons about information, and generates responses.

### RAG = Research

Lets the AI look through your information before answering.

### Agent = Worker

Lets the AI perform multiple steps, use tools, and take actions toward a goal.

### MCP = Connector Standard

Provides a standard way for AI applications to connect to tools and external data.

Once these four concepts make sense, most of the rest of modern AI architecture becomes much easier to understand.

## AI Term Breakdown

| Term | Plain-English meaning | Simple example |
|---|---|---|
| **AI** | The broad category: computers doing things that normally require human-like intelligence. | Recognizing images, answering questions |
| **Machine Learning (ML)** | AI that learns patterns from data instead of being explicitly programmed for every situation. | Spam detection |
| **LLM** | A Large Language Model. The AI model that understands and generates language. | GPT, Claude, Gemini, Llama |
| **Prompt** | The instructions or question you give the AI. | “Explain this firewall rule.” |
| **Context** | Information the AI can currently see while answering you. | Your prompt, previous messages, attached documents |
| **Token** | Small chunks of text that an LLM reads and generates. | Pieces of words or short groups of characters |
| **Context Window** | How much information the AI can consider at once. | A model reading a large document plus your conversation |
| **Reasoning** | The model working through a problem before answering or taking action. | Comparing several firewall rules before deciding which ones are risky |
| **RAG** | **Retrieval-Augmented Generation.** The AI searches your documents or data first, then uses what it finds to answer. | Asking an AI questions about your firewall documentation |
| **Embedding** | A mathematical representation of meaning used to find similar information. | Finding documents related to “VPN problems” even if they don't use those exact words |
| **Vector Database** | A database commonly used to store embeddings so AI can quickly find related information. | Searching thousands of internal documents for relevant sections |
| **Agent** | An AI system that can use tools and perform multiple steps toward a goal instead of only answering a question. | “Check these firewall rules, find risky ones, and create a report.” |
| **Agentic AI** | AI designed to decide what steps and tools it needs to complete a goal. | Reviewing policies, checking standards, and creating findings automatically |
| **Agent Loop** | The cycle an agent follows: understand, act, check the result, then decide what to do next. | Query firewall → review result → gather more data → generate findings |
| **Tool** | Something an AI or agent is allowed to use. | Web search, Python, database, API |
| **API** | A way for one program to communicate with another program. | An AI calling the Palo Alto API to retrieve security policies |
| **MCP** | **Model Context Protocol.** A standard way to connect AI applications to tools and data. | Giving an AI access to GitHub, databases, or firewall tools |
| **MCP Server** | A program that exposes tools or data through MCP. | A Palo Alto MCP server providing `get_rules`, `get_interfaces`, and `search_logs` |
| **Function Calling** | A way an LLM tells software which tool or function it wants executed. | AI requests `get_firewall_rule("Internet-Out")` |
| **Orchestration** | The logic that coordinates models, agents, tools, retries, and workflows. | One step gathers data, another analyzes it, and another creates a ticket |
| **Memory** | Information an AI system can keep or retrieve across interactions. | Remembering previous project decisions or your preferred report format |
| **Context Engineering** | Making sure the AI gets the right instructions, data, tools, and background at the right time. | Providing firewall policies, security standards, and analysis instructions together |
| **Agentic RAG** | RAG where the agent decides what information it needs to retrieve and when. | Searching different security documents based on what the agent discovers |
| **Multi-Agent System** | Multiple specialized agents working together on a larger task. | One agent gathers configs, another analyzes them, and another writes the report |
| **Human in the Loop** | Requiring a person to review or approve certain AI actions. | AI recommends a firewall change, but an engineer must approve it |
| **Fine-tuning** | Additional training that changes how a model behaves or responds. | Training a model to consistently use your company's terminology |
| **Inference** | Running a trained AI model to get an answer. | Asking an AI a question and receiving a response |
| **Hallucination** | When an AI confidently gives incorrect or made-up information. | Inventing a firewall rule that doesn't exist |
| **Guardrails** | Rules that limit what an AI or agent is allowed to do. | Letting an agent read firewall configs but preventing it from changing them |
| **Prompt Injection** | Instructions hidden in data that try to trick an AI into ignoring its real instructions. | A document tells an AI to ignore its security rules |

## The easiest way to understand the big pieces

Think of an AI system like an **employee at a computer**.

The pieces are not really a straight chain. The LLM is the intelligence behind the system, while the agent can use RAG, memory, APIs, and MCP as needed.

```text
                         +--> RAG
                         |    Search reference material
                         |
                         +--> Memory
                         |    Retrieve previous context
                         |
You --> Prompt --> LLM / Agent
                         |
                         +--> Tools / APIs
                         |    Run commands or access systems
                         |
                         +--> MCP
                              Standard way to expose tools
                              and data to AI applications
```

A simple way to remember it:

```text
LLM           = Brain
Agent         = Worker
RAG           = Research
Memory        = What it remembers
Tools / APIs  = Things it can use
MCP           = Standard connector
Orchestration = Workflow manager
Human Review  = Approval step
```

## Example: AI Firewall Analysis

Suppose you want an AI system to answer:

```text
"Which firewall rules allow ANY source?"
```

A simple workflow could look like this:

```text
You
 |
 | "Which firewall rules allow ANY source?"
 v
LLM / Agent
 |
 | Decides what information it needs
 |
 +--> MCP / API --> Palo Alto Firewall
 |                    |
 |                    +--> Retrieve security policies
 |
 +--> RAG --> Security standards and documentation
 |
 +--> Memory --> Previous decisions or project context
 |
 v
Analyze Policies
 |
 v
Generate Findings
 |
 v
Human Review
```

Another example would be:

```text
Goal:
"Find risky firewall policies."

        |
        v

Agent / LLM
        |
        | Decide what information is needed
        v

MCP Tool / API
        |
        v

Firewall
        |
        | Retrieve security policies
        v

Agent
        |
        +--> RAG --> Security standards
        |
        +--> Memory --> Previous decisions
        |
        v

Analyze Policies
        |
        v

Generate Findings
        |
        v

Human Review / Approval
```

The key idea is that the **LLM provides the intelligence**, while the **agent uses that intelligence to decide what actions to take**.

RAG, memory, APIs, tools, and MCP give the agent access to the information and capabilities it needs.
